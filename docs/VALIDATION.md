# Validation report (simulation)

Generated by `npm run validate` on 2026-11-06 · seed 20261101.

> **What this shows and what it does not.** Synthetic users with known abilities are run through the *real* engine. This measures the quality of the measurement machinery — estimation error, interval calibration, adaptivity, tracking and robustness. Simulated responses follow the engine’s own response model, so this does **not** establish that the tasks measure the intended constructs in real people; that requires a pilot study (see the technical report, “Limitations”).

## 3. Brain Twin tracking of real change

100 learners practise Working Memory every ~2 days for 40 days (true gain 0.6–1.4 logits, saturating). We compare the twin (with drift + per-session process noise) to a static Bayesian model that never forgets.

| Model | RMSE over all sessions | RMSE, last 6 sessions | 80 % interval coverage |
|---|---|---|---|
| Brain Twin (drift + process noise) | 0.30 | 0.25 | 72.9 % |
| Static Bayesian (no forgetting) | 0.39 | 0.45 | 33.1 % |

Reading: without drift the posterior becomes over-confident and lags behind real learning (coverage collapses to about a third). The twin’s drift keeps intervals close to honest while it follows growth. Coverage remains a little under the nominal 80 % because learners also improve *within* a session, which a per-session model cannot see — a known, documented limitation.

## 4. Are projections honest?

Reading: coverage at or above nominal means the bands are, if anything, cautious — the intended behaviour for a feature that must “never present a projection as certainty”.
